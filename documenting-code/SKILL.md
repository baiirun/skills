# Documenting Code

Before writing the code, read each principle whose condition matches the work. They are short; read them in full rather than from memory of their titles.

| When the work involves | Read |
|---|---|
| Writing or editing source comments, workaround notes, or commented-out code | `principles/comment-the-why.md` |
| The same instruction, comment, or correction appearing a second time | `principles/encode-lessons-in-structure.md` |

For feature or capability docs, call the Skill tool with `feature-contract-docs`. For an explicit cleanup pass over existing comments, call the Skill tool with `no-comments`.

Done when: every row whose condition matches the work has had its principle read in full, and the code follows it, including its test where it has one.
